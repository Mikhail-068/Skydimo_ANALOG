# Архитектура «Контура»

Локальное приложение для Windows 10/11 с .NET Desktop Runtime 8. Снимок исходников от 18 ноября 2026 года, рабочее дерево без коммита.

| Компонент | Ответственность |
|---|---|
| [Окно](../../MainWindow.cs) | Рычаг выбирает выключение и режим. Он запускает автоматический поиск единственного CH340 и отключение при выключении. Верхнее положение левой ветки открывает палитру. Выбранный оттенок сразу передаётся рабочему циклу. Палитра остаётся видимой до смены положения рычага. Диалог «Другой цвет…» редактирует активную кнопку, её оттенок сохраняется в настройках. Регулятор яркости расположен под предпросмотром. [Схема дисплеев](../../MonitorSelector.cs) отражает подключённые мониторы, выделяет выбранный источник захвата и обновляется при изменении конфигурации Windows. Окно отображает последнее состояние рабочего цикла. В [предпросмотре](../../LedPreview.cs) вид сзади показывает маршрут 65 светодиодов. Маршрут можно нарисовать на задней стороне монитора. Настройки хранят 65 нормализованных точек от начала к концу. Захват экрана зеркально переводит координаты заднего вида в координаты экрана и берёт цвета в порядке ленты. Без своего маршрута используется штатная раскладка и настройка направления. [AmbientWall.cs](../../AmbientWall.cs) строит рассеянный ореол по цветам того же кадра. Цвета, отрисовка и управление элементами окна собраны в [WindowStyle.cs](../../WindowStyle.cs). |
| [Захват](../../DesktopCapture.cs) | Уменьшает кадр выбранного дисплея через GDI, усредняет цвет по 65 ячейкам. Изображение существует в памяти. |
| [Рабочие циклы](../../LightingEngine.cs) | Независимые циклы захвата и отправки по 20 раз в секунду. Передача использует последний доступный кадр либо выбранный однотонный цвет. |
| [Протокол и хранилище](../../Lighting.cs) | Раскладка 17 / 31 / 17, преобразование RGB и сборка 201-байтового сообщения. Локальные настройки в JSON, журнал с ротацией. |
| [COM-порт](../../SerialLink.cs) | Windows Win32 API, 115200 8N1, эксклюзивный доступ, идентификация SK0127. Запись кадров начинается после ответа контроллера. |

### Границы и проверка

- Для вывода нужен доступный USB-порт с устройством SK0127. В режиме предпросмотра приложение не занимает порт.
- Два цикла обмениваются последними данными в памяти, без очереди устаревающих кадров. Обновление цвета не складывается в очередь при временной задержке.
- Кадр подтверждён по локальному журналу установленной Skydimo и по формату совместимого драйвера. Журнал программы сохраняет ошибки и паузы, без дампа пикселей.
- Порядок светодиодов соответствует заводской раскладке SK0127. Физическая ориентация конкретной ленты проверяется по изображению на мониторе.

Источники для протокола и последовательного ввода-вывода: [описание протокола GlowSync](https://github.com/skybots-tg/glowsync#skydimo-protocol), [реализация драйвера HyperHDR](https://github.com/awawa-dev/HyperHDR/blob/master/sources/led-drivers/serial/DriverSerialSkydimo.cpp) и [настройка последовательного порта Windows](https://learn.microsoft.com/en-us/windows/win32/devio/configuring-a-communications-resource).
